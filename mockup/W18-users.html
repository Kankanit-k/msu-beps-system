ℹ️ ผู้ใช้หนึ่งคนมี หนึ่งบทบาท และ หนึ่งขอบเขต ตามตาราง app_user — app_role_id บอกว่าทำอะไรได้ · org_unit_id บอกว่าเห็นข้อมูลของใคร (NULL = ทุกหน่วยงาน)
⚠️ ต้องตัดสินใจก่อนเริ่มเขียนโค้ด — app_role มี CHECK constraint ล็อกไว้ 4 ค่า (admin · budget_office · faculty_officer · viewer) และไม่มีบทบาท "ผู้อนุมัติ" แยก ทั้งที่ SA กำหนดว่าผู้เสนอกดอนุมัติเรื่องของตัวเองไม่ได้ · ตอนนี้จึงตกเป็นภาระของ admin ซึ่งแปลว่าผู้ดูแลระบบมีอำนาจอนุมัติเชิงนโยบายด้วย — ถ้าไม่ต้องการแบบนี้ ต้องเพิ่ม role approver ใน schema ก่อน

กติกาสิทธิ์ที่ระบบต้องบังคับ

  • ผู้เสนอกดอนุมัติเรื่องของตัวเองไม่ได้ — บังคับที่ระดับหลังบ้าน ไม่ใช่แค่ซ่อนปุ่ม เพราะเรียก API ตรงได้
  • ขอบเขตต้องกรองที่ query ไม่ใช่ที่หน้าจอ — faculty_officer ที่ผูกกับคณะวิศวฯ ต้องดึงข้อมูลคณะอื่นไม่ได้แม้จะแก้ URL เอง
  • เปลี่ยนสิทธิ์ไม่ย้อนหลัง — รายการที่เคยอนุมัติไปแล้วยังคงชื่อผู้อนุมัติเดิม แม้คนนั้นจะถูกถอนสิทธิ์ภายหลัง
  • ระบบไม่เก็บรหัสผ่านเอง — ยืนยันตัวตนผ่าน MSU Account (SSO) ตารางนี้เก็บแค่บทบาทและขอบเขต
  • บัญชีที่ไม่เข้าใช้เกิน 180 วันถูกระงับอัตโนมัติ — ปลดล็อกได้โดยผู้ดูแลระบบ ไม่ลบทิ้งเพราะยังต้องอ้างในประวัติการอนุมัติ
