
**วิธีรวม** — ยัดทุกหน้าไว้พร้อมกันไม่ได้เพราะ `id` ซ้ำกันข้ามหน้าถึง 14 ตัว
(`detail` · `cnt` · `f-year` · `f-q` · `k-n` …) สคริปต์จึง **mount ทีละหน้า** —
ใน DOM มีเนื้อหาของหน้าเดียวเสมอ `id` จึงไม่มีวันชนกัน
ส่วน JS ของแต่ละหน้าถูกห่อไว้ใน `init()` ของตัวเอง ตัวแปรไม่รั่วถึงกัน
ฟังก์ชันที่ถูกเรียกจาก `onclick=` ใน HTML (W6, W7) ถูก export ออกมาเป็น global ให้อัตโนมัติ
— แต่ handler ที่ **สร้างตอนรันไทม์** (เช่นตารางแผนการรับของ W7) ตัวสร้างมองไม่เห็น
ต้องประกาศ `window.<ชื่อ> = <ชื่อ>` เองท้ายไฟล์ ไม่อย่างนั้นจะตายเงียบเฉพาะในฉบับไฟล์เดียว

## ธีม

ใช้ธีมจาก **MSU Starter Kit** (Materio MUI Next.js Admin Template) — `src/@core/theme`
โดยยกมาเฉพาะ **design token** (สี · ฟอนต์ · เงา · มุมโค้ง) ไม่ได้คัดลอกซอร์สของเทมเพลต
เพราะ mockup ชุดนี้เป็น HTML/CSS ล้วน ไม่ได้ใช้ React/MUI

| token                     | ค่าจากธีม                                                   |
| ------------------------- | ----------------------------------------------------------- |
| primary                   | `#6D4CFF` (main) · `#5938E0` (dark) · `#8B6FFF` (light)     |
| warning · success · error | `#FFB400` · `#56CA00` · `#FF4C51`                           |
| สีฐานข้อความ/เส้น         | `rgb(46 38 61)` = `#2E263D` — ไล่ความทึบ .9 / .7 / .63 / .4 |
| พื้นหลัง                  | `#F4F5FA` (default) · `#FFFFFF` (paper) · `#F0EFF0` (track) |
| เงา                       | `0 2px 4px rgb(46 38 61 / .16)` · `0 4px 10px / .20`        |
| มุมโค้ง                   | `6px` (`shape.borderRadius`)                                |
| ฟอนต์                     | **Sarabun** (เนื้อความ) · **Manrope** (ตัวเลข/หัวข้อ)       |

ชื่อ CSS variable ใน `beps.css` **คงเดิมทุกตัว** หน้าจอทั้ง 20 หน้าจึงเปลี่ยนธีมตามโดยไม่ต้องแก้ทีละหน้า
เลย์เอาต์ · ระยะห่าง · โครงหน้าจอ ไม่เปลี่ยนเลย

**จุดที่จงใจไม่ทำตามธีมเป๊ะ** — ธีมกำหนดให้ตัวอักษรบน chip ใช้สี `main` บนพื้นโปร่ง 8–16%
ซึ่ง contrast ต่ำกว่าเกณฑ์ WCAG AA (เช่น `#FFB400` บนพื้นเหลืองอ่อน ได้ราว 1.9:1)
`--gold` · `--green` · `--red` จึงใช้เฉดเข้มกว่าที่คงโทนสีเดิมไว้ ทำให้ทุก chip ผ่าน AA (4.7–6.0:1)

## ข้อมูลจริง เทียบ ข้อมูลตัวอย่าง

`.gitignore` ของโปรเจกต์ห้าม commit ข้อมูลการเงินภายในมหาวิทยาลัย และ repo นี้เป็น **public**
`mockup/assets/data.js` (งบ · ต้นทุน · ค่าเสื่อม · นิสิต แยกครบ 20 คณะ 230 หลักสูตร) จึง**ไม่อยู่ใน git**

ทุกหน้าโหลดข้อมูลแบบนี้:

```html
<script src="assets/data.sample.js"></script>
<!-- ถ้ามี data.js ในเครื่อง จะโหลดทับให้เอง -->
<script src="assets/data.js"></script>
```

| สถานการณ์                                | เห็นตัวเลขอะไร                                            |
| ---------------------------------------- | --------------------------------------------------------- |
| clone จาก GitHub มาเปล่าๆ                | ชุดตัวอย่าง + **แถบแดงเตือนบนทุกหน้า**ว่าไม่ใช่ตัวเลขจริง |
| วาง `data.js` ของจริงลง `mockup/assets/` | ตัวเลขจริง แถบแดงหายไปเอง                                 |

ชุดตัวอย่างสร้างจาก `mockup/make-data-sample.mjs` — สุ่มรบกวนตัวตั้งรายหลักสูตร
แล้ว**คำนวณค่าที่เหลือใหม่ตามสูตรเดิมทั้งหมด** ความสัมพันธ์ทุกสูตรจึงยังถูกต้อง
(`TR = st + own` · `TC = TFC + TVC` · `Q* = TFC ÷ (R − AVC)` · สูตรที่ 7 เมื่อ CM ≤ 0)
หน้าจอทุกหน้าจึงทำงานเหมือนใช้ข้อมูลจริง แต่ยอดรวมห่างจากของจริงราว 30%

```bash
node mockup/make-data-sample.mjs   # สร้างใหม่เมื่อ data.js เปลี่ยน
```

## สิ่งที่เปลี่ยนจาก prototype v8-1

หน้า W1–W7 และ W10 ใช้ markup และตรรกะเดิม **ไม่แก้สูตรแม้แต่บรรทัดเดียว** ส่วนที่เพิ่มคือ

1. แยกไฟล์ต่อหน้า และแยก CSS / ข้อมูล / สูตร ออกเป็น `assets/`
2. topbar เพิ่ม **ปีงบประมาณ**, **รอบคำนวณที่กำลังดู** และ **ผู้ใช้ที่เข้าสู่ระบบ** (SA §9.1 ข้อ 2, §9.2 ข้อ 9)
3. เพิ่ม **แถบเตือนข้อจำกัดของข้อมูล** ในทุกหน้าที่แสดงส่วนเกินหรือ Q\*
4. sidebar เพิ่มกลุ่มเมนู ปันส่วนต้นทุน · จัดการข้อมูล · ตั้งค่าระบบ พร้อมไอคอนล็อกบอกว่าเห็นตาม role
5. **W7 เพิ่มส่วนที่ 2 — วิเคราะห์สัดส่วนจำนวนนิสิตเพื่อหาจุดคุ้มทุน** (`assets/page-admission-mix.js`)

## W7 ส่วนที่ 2 — วิเคราะห์สัดส่วนจำนวนนิสิต

ความต้องการจากที่ประชุม: ได้จุดคุ้มทุน**รวม**แล้วต้องแตกต่อตาม**แผนการรับนิสิต** —
ไทย (ปกติ/พิเศษ) · ต่างชาติ (ปกติ/พิเศษ) · หลักสูตรต่อเนื่อง
ใช้ได้ทั้งตอนปรับปรุงหลักสูตรปัจจุบันและตอนเสนอเปิดหลักสูตรใหม่

- กรอกแผนได้ 2 แบบต่อแถว — **คงค้างรวม** หรือ **รับต่อปี × จำนวนปี**
  (หลักสูตรต่อเนื่องใส่ 2 ปี ไม่ต้องมีเคสพิเศษ)
- ผลรายประเภท: สัดส่วน · รายรับ/หัว/ปี · TFC ที่ปันมา · TVC · CM/หัว · Q\* ของส่วนที่ปันมา · ส่วนเกิน
- **Goal Seek** — ตรึงประเภทอื่นไว้ แล้วหาว่าประเภทที่เลือกต้องรับกี่คนจึงคุ้มทุนทั้งหลักสูตร
  ค่านี้ไม่ต้องปันส่วน TFC จึงไม่ขึ้นกับส่วนผสมที่กรอก ต่างจากคอลัมน์ Q\* รายแถว
- สลับฐานรายได้ที่แถบด้านบนแล้วตารางคำนวณใหม่ให้เอง ไม่ทิ้งตัวเลขของฐานเดิมค้างไว้

ตรรกะพอร์ตจาก `packages/calc-engine/src/admission-mix.ts` แบบหนึ่งต่อหนึ่ง
(mockup เป็น static HTML ไม่มี bundler จึงคัดลอกมา) ตัวเลขตรงกับแผง `X9:AD22`
ของชีต `4.จุดคุ้มทุนหลักสูตร(ใหม่)` ทุกช่อง แต่**แก้นิยามที่ชีตเดิมตั้งชื่อผิด** —
ค่าที่ชีตเรียกว่า "จุดคุ้มทุนของหลักสูตร" จริงๆ คือ _ส่วนเกิน_ ที่นี่จึงแยกเป็นคนละคอลัมน์
รายละเอียดอยู่ใน [`../db/README.md`](../db/README.md)

## W16–W19 — หน้าที่ SA §9 ยังไม่ได้ระบุ

ตารางหน้าจอใน SA §9 ครอบคลุมเฉพาะ W0–W15 ซึ่ง**ไม่มีหน้าจัดการตัวทะเบียนหลักสูตรเอง**
มีแต่ W7 ที่เป็นเครื่องจำลอง (`scenario_plan`) — สร้าง `program` จริงไม่ได้
ทั้งที่ ER v2 มีตาราง `program` + `program_version` และ SA ระบุเองว่า
`program_version` รองรับการปรับปรุงหลักสูตรรอบ มคอ.

## ข้อควรระวัง

- **ค่าเสื่อมราคาอาคารยังไม่มีข้อมูล** — TFC และ TC ต่ำกว่าจริง ส่วนเกิน +32.8 ลบ. สูงเกินจริง
  และ Q\* ทุกระดับต่ำกว่าที่ควรเป็น · ตัวเลขชุดนี้ยังไม่ใช่ตัวเลขสำหรับนำเสนอเป็นข้อสรุป
- `master-data.js` เป็น **ข้อมูลจำลอง** — โครงสร้างอ้างอิงตารางจริงใน `db/01_schema.sql`
  แต่ชื่อผู้ใช้ วันเวลา และสถานะ workflow เป็นตัวอย่างเพื่อให้เห็นรูปแบบหน้าจอ
- W12 ใช้ `tfcOffice` เป็นตัวแทนของยอดที่ปันส่วนในตารางรายคณะ
  ระบบจริงต้องอ่านจาก `cost_allocation_line.method`
- W16 จับคู่กับ `RAW.PROGS` ด้วย (ชื่อหลักสูตร + คณะ + ระดับ) เพราะชุดข้อมูล v8-1 ไม่มี `program_code`
  ระบบจริงต้องจับคู่ด้วย `program_code` จากระบบทะเบียนเท่านั้น
