1สรุป

  • ของเดิมใช้ต่อได้มาก: หน้านี้มี 3 ขั้นตามที่ประชุมขออยู่แล้ว (คำนวณ → สัดส่วนนิสิต → สรุป) · สิทธิ์ตรงกับมติแล้ว (ผู้บริหาร ม./คณะ เข้าไม่ได้ · อาจารย์เห็นแค่หลักสูตรของตน) · ตารางแจกแจงมี 5 กลุ่มครบ รวมคอลัมน์เทียบเข้า · มีตารางเทียบรวม/ไม่รวมเงินแผ่นดินคู่กัน
  • ต้องเพิ่ม: แถบขั้นตอนบางๆ ติดด้านบน · แก้ต้นทุนผันแปรรายหมวด · แสดงค่าธรรมเนียม 3 แบบ (ต่อภาค / ต่อปี / ตลอดหลักสูตร) · แถวต้นทุนรวมในตารางแจกแจง · กราฟโครงสร้างต้นทุน · ลายน้ำ “ฉบับร่าง” · ปุ่ม Submit ที่ล็อกข้อมูล · คอลัมน์รายได้และต้นทุนในตารางสรุปก่อน/หลังปรับ
  • ต้องแก้: อาจารย์เข้ามาแล้วระบบเลือกหลักสูตรให้ทันที (ตอนนี้ยังต้องเลือกจากรายการที่มีตัวเลือกเดียว) · หัวรายงานเปลี่ยนเป็น “เอกสารปรับปรุงหลักสูตรเดิม”
  • ข้อจำกัดใหญ่: ยังไม่มีฐานข้อมูลจริง (ไม่มี apps/api) ทั้งร่างและผลที่บันทึกอยู่ใน localStorage · “Submit แล้วล็อก” ทำหน้าจอได้ แต่จะล็อกได้จริงข้ามเครื่องก็ต่อเมื่อมี DB (ข้อ D6)

2มติที่ประชุม vs ของเดิม

ข้อในเอกสารตอนนี้รอบนี้
1 · ผู้มีสิทธิ์: กองแผน / เจ้าหน้าที่คณะ / อาจารย์ (หลักสูตรตน)ตรงแล้ว — ANALYZE_ROLES = universityAdmin, deptAdmin, lecturerคง
1 · ผู้บริหาร ม./คณะ ไม่เห็นเมนูวิเคราะห์ตรงแล้ว — middleware กันไว้ เมนูซ่อนคง
1 · Default view ตามสิทธิ์ ไม่ต้องเลือกเองคณะตั้งให้แล้ว แต่ หลักสูตรยังต้องเลือก และต้องกด “ยืนยันข้อมูลหลักสูตร”แก้
2 · Stepper บาง ติดด้านบน คลิกข้ามขั้นได้Stepper อยู่บนแต่ไม่ติด · แถบ ถัดไป/ย้อนกลับ ติดด้านล่าง · ขั้น 2–3 ล็อกจนกดยืนยันขั้น 1แก้
3.1 · เทียบ ก่อน | หลัง × รวม/ไม่รวมเงินแผ่นดินมี (การ์ด ② สองกลุ่มคู่กัน)คง
3.1 · แก้ได้: จำนวนนิสิต + ค่าเทอมมี (เฉพาะ 2 ช่องนี้)คง
3.1 · ห้ามแก้: เงินแผ่นดิน, ต้นทุนคงที่ (ไม่มีไอคอนปากกา)ล็อกอยู่แล้วคง + ตรวจไอคอน
3.1 · แก้ได้: ต้นทุนผันแปรรายหมวดล็อก (basicOnly เปิดเฉพาะ 2 ช่อง)เพิ่ม
3.1 · ค่าธรรมเนียม ต่อภาค / ต่อปี / ตลอดหลักสูตรการ์ด ② มีแค่ “ต่อคนต่อปี” · ตาราง ③ กรอก “ต่อภาค”เพิ่ม
3.1 · คำนวณสดมีแล้วคง
3.2 · ตารางแจกแจง 5 กลุ่ม (ไทย ปกติ/พิเศษ · ต่างชาติ ปกติ/พิเศษ · เทียบเข้า)มีครบ (StudentMixTable)คง
3.2 · เงินแผ่นดินเฉพาะนิสิตไทยต่างชาติล็อก 0 · ไทยพิเศษตั้งต้น 0 แต่แก้ได้ · เทียบเข้าได้เงินแผ่นดินD3
3.2 · ปันต้นทุนคงที่ลงทุกคอลัมน์ปันตามสัดส่วนจำนวนนิสิตของคอลัมน์D2
3.2 · แถว “ต้นทุนรวม” (คงที่ + ผันแปร)ไม่มีเพิ่ม
3.3 · พรีวิวรวมทั้งหมด + กราฟโครงสร้างต้นทุน + กราฟสถานะขั้นสรุปมีตารางเทียบ + กราฟจุดคุ้มทุน · ไม่มีกราฟคงที่ vs ผันแปร · ไม่มีตารางแจกแจงในขั้นนี้เพิ่ม
3.3 · หัวรายงาน “เอกสารปรับปรุงหลักสูตรเดิม”“รายงานการวิเคราะห์จุดคุ้มทุนหลักสูตร” + ป้ายเล็ก “หลักสูตรเดิม”แก้
3.3 · Draft Save ลงฐานข้อมูลบันทึกได้ แต่อยู่ใน localStorageD6
3.3 · พิมพ์ร่าง มีลายน้ำ “ฉบับร่าง”ไม่มีลายน้ำเพิ่ม
3.3 · Submit → ลายน้ำหาย + ล็อกห้ามแก้ไม่มีสถานะ (แก้/ลบได้ตลอด)เพิ่ม (D5, D6)
4 · ตารางสรุปก่อน/หลัง 4 คอลัมน์ + ไฮไลต์ + แถวรวมคณะRankingCard (หน้าจุดคุ้มทุนคณะ) มี นิสิต · Q* · กำไร · สถานะ + แถวรวม · ไม่มี รายได้/ต้นทุน · ไม่ไฮไลต์เฉพาะแถวที่ปรับแก้ (D7, D8)

3แถบขั้นตอน + โครงหน้า

แถบติดบน (สูง ~40px): ① คำนวณตั้งต้น ✓ ── ② แจกแจงแผนรับนิสิต ── ③ พรีวิวรายงาน & ยืนยัน · ด้านขวา: หลักสูตร · สถานะ ร่าง / ยืนยันแล้ว 🔒คลิกขั้นไหนก็ได้ทันที · ไม่มีคำอธิบายใต้ชื่อขั้น (เอาออกให้บาง) · จอแคบเหลือเลขวงกลม + ชื่อขั้นปัจจุบัน
เนื้อหาขั้นที่เลือกขั้นที่ 1 แสดงทันทีเพราะหลักสูตรถูกเลือกให้แล้ว (อาจารย์) · เจ้าหน้าที่คณะ/กองแผน เลือกหลักสูตรจาก combobox ที่หัวขั้นที่ 1
แถบล่าง (คงไว้แต่ย่อ): ← ย้อนกลับ · ถัดไป →D9 — ตัดออกได้ถ้าที่ประชุมอยากให้ใช้แถบบนอย่างเดียว
  • ทำ WizardStepper เป็น position: sticky; top: <ความสูง navbar> แบบบาง (ใช้ props เดิม onGo) · ลบ prop hints ออกจากหน้านี้
  • เลิกกฎ “ขั้น 2–3 ล็อกจนยืนยันขั้น 1” — ล็อกเฉพาะเมื่อ ยังไม่มีหลักสูตร หรือ คณะยังไม่ล็อกวิธีปันต้นทุนคงที่ (บอกเหตุผลใน tooltip ของขั้นที่กดไม่ได้)
  • ปุ่ม “ยืนยันข้อมูลหลักสูตร” (ตั้งเทอม/ปีก่อน) ตัดออก: เทอม/ปี ย้ายไปอยู่ในแถวค่าธรรมเนียมของขั้นที่ 1 แทน (ข้อ 4)

8ข้อสรุป (ยืนยันแล้ว 25 ต.ค. — ใช้ตามที่แนะนำทั้ง 9 ข้อ)

D1 · ต้นทุนผันแปรที่แก้ ใช้กับทั้งสองกรณีหรือแยกต้นทุนไม่เกี่ยวกับว่ามีเงินแผ่นดินหรือไม่ แต่โค้ดตอนนี้เก็บก้อนตัวเลขแยกสองกรณี
แนะนำ: แก้ครั้งเดียวใช้ทั้งสองกรณี (จำนวนนิสิต/ค่าเทอม/ต้นทุนผันแปร ตรงกันทั้งคู่ ต่างกันแค่เงินแผ่นดิน)
D2 · ต้นทุนคงที่ลงแต่ละคอลัมน์ในตาราง 5 กลุ่มเอกสารเขียน “หารเฉลี่ยแล้วทอนกระจายลงทุกคอลัมน์” — อ่านได้ 2 แบบ: (ก) หารเท่ากันทุกคอลัมน์ (ข) ตามสัดส่วนจำนวนนิสิต (แบบเดิม) · แบบ (ก) ทำให้คอลัมน์ที่ไม่มีนิสิตแบกต้นทุนและขาดทุนลอยๆ
แนะนำ: (ข) คงเดิม — เป็นการ “หารเฉลี่ยต่อหัว” และตรงกับชีตแท็บ 4
D3 · เงินแผ่นดินของ ไทยภาคพิเศษ และ เทียบเข้ามติ: “เฉพาะนิสิตไทย” · ตอนนี้ ไทยพิเศษ = 0, เทียบเข้า = ได้ (ตามชีต Y14)
แนะนำ: คงตามชีต (ไทยปกติ + เทียบเข้า ได้ · ไทยพิเศษ/ต่างชาติ ไม่ได้) และล็อกห้ามแก้ — ถ้ากองแผนยืนยันว่าเทียบเข้าไม่ได้ ค่อยปรับ
D4 · ค่าตั้งต้นคอลัมน์ “หลังปรับปรุง”ตอนนี้ระบบตั้งเป็นจำนวนนิสิตขั้นต่ำที่คุ้มทุนให้เอง (ตัดสินใจ 18 ต.ค.) · เอกสารยกตัวอย่างเริ่มที่ 83 แล้วปรับเป็น 100
แนะนำ: ตั้งต้น = ตัวเลขปัจจุบัน + ปุ่ม “ใช้จำนวนขั้นต่ำที่คุ้มทุน” ข้างช่องจำนวนนิสิต (ผู้ใช้เห็นก่อน → หลัง ชัดกว่า)
D5 · ใครกด Submit / ใครปลดล็อก
แนะนำ: Submit = ผู้ที่ออกรายงานได้อยู่แล้ว (กองแผน + อาจารย์ ตาม canExportReport) · deptAdmin บันทึกร่าง/พิมพ์ร่างได้ · ปลดล็อก = กองแผนเท่านั้น (หลังได้รับบันทึกขออนุมัติ)
D6 · ที่เก็บข้อมูล (Draft Save ลง DB + Lock)ตอนนี้เป็น localStorage → ล้างเบราว์เซอร์ก็ปลดล็อกได้ และผู้บริหารเครื่องอื่นไม่เห็นผล · งานเดียวกับ D4 ของแผนหน้าจุดคุ้มทุนคณะที่ยังค้าง
แนะนำ: รอบนี้ทำ UI + สถานะใน localStorage ให้ครบก่อน (เปลี่ยนเป็น API ได้ทีหลังโดยไม่แก้หน้า) แล้วทำ DB เป็นงานแยกต่อทันที — ต้องเลือกที่ตั้ง Postgres ก่อน
D7 · สีไฮไลต์หลักสูตรที่ปรับเอกสารให้น้ำเงิน หรือแดง · ระบบใช้แดง = ขาดทุน/ไม่ผ่านอยู่แล้ว
แนะนำ: น้ำเงิน + ไอคอน ✎
D8 · ตารางสรุปใช้ผลไหน
แนะนำ: ผลที่ Submit แล้วเป็นหลัก · ถ้ายังไม่มี ใช้ร่างล่าสุดพร้อมป้าย “ร่าง”
D9 · แถบ ถัดไป/ย้อนกลับ ด้านล่าง
แนะนำ: คงไว้แบบย่อ (บางคนเลื่อนลงสุดแล้วหาปุ่มต่อ) — ตัวนำทางหลักคือแถบบน

9ลำดับงาน

  1. IP-1 แถบขั้นตอนบาง ติดบน คลิกข้ามได้ · เลิกบังคับปุ่ม “ยืนยันข้อมูลหลักสูตร” · Default view ของอาจารย์
  2. IP-2 ขั้นที่ 1: ค่าธรรมเนียม 3 แบบ · แก้ต้นทุนผันแปรรายหมวด (D1) · ค่าตั้งต้นหลังปรับ (D4) · ตรวจว่าเงินแผ่นดิน/ต้นทุนคงที่ไม่มีปากกา
  3. IP-3 ขั้นที่ 2: แถวต้นทุนรวม · ล็อกเงินแผ่นดิน (D3) · test ผลรวม = ขั้นที่ 1
  4. IP-4 ขั้นที่ 3: พรีวิวในหน้า · หัวเอกสาร · ตารางแจกแจง · กราฟโครงสร้างต้นทุน
  5. IP-5 สถานะ DRAFT/SUBMITTED · ลายน้ำฉบับร่าง · กล่องยืนยัน Submit · ล็อกหน้าเมื่อ SUBMITTED (D5)
  6. IP-6 ตารางสรุปเปรียบเทียบ: คอลัมน์รายได้/ต้นทุน · ไฮไลต์แถวที่ปรับ (D7, D8)
  7. IP-7 ทดสอบในเบราว์เซอร์ทั้ง 3 บทบาท (กองแผน/deptAdmin/อาจารย์) × ป.ตรี/โท × พิมพ์ร่าง/ฉบับจริง · ตัวเลขตรงชีต · agent แยกตรวจ · ภาพหน้าจอเก็บไว้ทำคู่มือ
  8. DB (แยก) API + Postgres สำหรับผลจำลองและสถานะล็อก (D6) · security review ก่อน deploy
