1สรุป

มติให้การจำแนกต้นทุนคงที่/ผันแปรเป็น นโยบายระดับคณะ ทุกหลักสูตรในคณะใช้เกณฑ์ชุดเดียวกัน เกณฑ์ของมหาวิทยาลัย (Excel) เป็นค่าตั้งต้น และค่าที่ตั้งจะล็อกเมื่อยืนยันหรือพิมพ์ฉบับจริง

ระบบมีอยู่แล้วประมาณครึ่งหนึ่ง ทั้ง ขั้นที่ 3 (วิธีปันส่วน) และกฎการล็อก/ยกค่าปีก่อน ทำไว้ที่ /admin/fixed-cost-lock ตั้งแต่ 25 ต.ค. สิ่งที่ยังไม่มีคือขั้นที่ 1–2 ในระดับคณะ ตอนนี้มีแค่หน้ากติกาผังบัญชีระดับมหาวิทยาลัยที่ทำเมื่อเช้า

เสนอให้รวมเป็น หน้าเดียว 3 ขั้น ต่อยอดจากหน้าวิธีปันส่วนเดิม และใช้การล็อกชุดเดียวกัน ส่วนหน้ากติกาผังบัญชีระดับมหาวิทยาลัยเปลี่ยนบทบาทเป็นที่ตั้งค่าตั้งต้น (Default Baseline) ของทุกคณะ
ข้อจำกัดเดิมยังอยู่ แอปยังไม่มีข้อมูลงบรายบรรทัดแยกคณะ (AR-1/AR-2 ใน PLAN-2026-10-27-account-rules-calc.html) จึงยังคำนวณใหม่ตามการจำแนกไม่ได้ หน้าตั้งค่าทำได้ก่อน แต่ตัวเลขจะเปลี่ยนตามได้ก็ต่อเมื่อทำ AR-1/AR-2 เสร็จ

2มติ vs ของเดิม

มติของเดิมในระบบสถานะ
1. เป็นนโยบายระดับคณะ ห้ามตั้งรายหลักสูตรวิธีปันส่วน: ระดับคณะอยู่แล้ว · การจำแนก: มีแค่ระดับมหาวิทยาลัย (account-rules)บางส่วน
1. ผู้ตั้งค่า = เจ้าหน้าที่คณะ + ผู้บริหารคณะ (+ มหาวิทยาลัย) · อาจารย์ไม่เห็นเมนูdeptAdmin + universityAdmin ตั้งได้ · facultyExec อ่านอย่างเดียว · อาจารย์ไม่เห็นอยู่แล้วต่าง (D1)
ขั้น 1. ดึงหมวดรายจ่ายจาก API ระบบบัญชีไม่มี API · รายการมาจาก Excel แท็บ Masterแยกหมวด (113 คีย์) · หน้าผังบัญชี ERP เป็นข้อมูลจำลองยังไม่มี
ขั้น 1. ค่าตั้งต้นตาม Excel มหาวิทยาลัยaccount-rules มีค่าตาม Excel + แก้ได้แบบอนุมัติ (ทำเมื่อเช้า)มี
ขั้น 2. คณะเลือก คงที่ 100% / ผันแปร 100% / แบ่ง %ฟอร์มใน account-rules มีครบ 3 แบบ (+ ยังไม่จำแนก) แต่เป็นระดับมหาวิทยาลัยย้ายมาคณะ
ขั้น 3. วิธีปันส่วน: รายหัว / เท่ากันต่อหลักสูตร / % ตามระดับ/admin/fixed-cost-lock มีครบมี
3.1 เก็บแยกรายปีการศึกษา ไม่กระทบย้อนหลังlockStore เก็บราย “ปี × คณะ” แล้ว · แต่ข้อมูลต้นทุนเป็นปีงบประมาณต่าง (D3)
3.2 ยังไม่ตั้งค่า → ยกค่าปีก่อน ไม่ล็อกระบบมีแล้ว (ปีก่อน → Excel)มี
3.3 ยืนยัน/พิมพ์ฉบับจริง → ล็อกทันที · ปลดต้องมีบันทึกข้อความล็อกเมื่อหลักสูตรแรก Submit · กองแผนปลดล็อก · การพิมพ์ฉบับจริงยังไม่ล็อกเพิ่ม Print

สิ่งที่พบจากข้อมูล: ในชีต หมวดรายจ่ายเดียวกันมีทั้งรายการคงที่และผันแปร เช่น 300 ค่าตอบแทน คงที่ 9 / ผันแปร 8 รายการ และ 800 เงินอุดหนุน คงที่ 6 / ผันแปร 17 / 50:50 1 รายการ ถ้าคณะจำแนกที่ระดับหมวดรายจ่าย (12 หมวด) ค่าตั้งต้นจะไม่ตรงกับ Excel ตัวอย่างในมติ (ค่าซ่อมบำรุงอาคาร, ค่าวัสดุการศึกษา) ก็เป็นระดับหมวดย่อย → ดู D2

3โครงหน้า (ต่อยอด /admin/fixed-cost-lock)

คณะ ▾ · ปีการศึกษา ▾ · สถานะ: ใช้ค่าตั้งต้น / ยกจากปี 2567 / คณะตั้งเอง / 🔒 ล็อกแล้ว
Stepper: ① หมวดรายจ่าย → ② จำแนกคงที่/ผันแปร → ③ วิธีปันส่วน → ④ บันทึก
② ตารางหมวดรายจ่าย (จัดกลุ่มตามหมวดรายจ่าย ยุบ/ขยายได้) แถว = หมวดย่อย · ค่าตั้งต้น (มหาวิทยาลัย) · ค่าของคณะ [คงที่|ผันแปร|แบ่ง %] · ยอด · ป้าย “ต่างจากค่าตั้งต้น” ปุ่มตั้งทั้งกลุ่ม · คืนค่าตั้งต้นรายแถว/ทั้งหมด · ค้นหา · แบ่งหน้า
สรุปผลTFC/TVC ของคณะ: ค่าตั้งต้น vs ค่าที่ตั้ง (ลบ.) · จำนวนรายการที่ต่างจากค่าตั้งต้น · ยังไม่จำแนก n รายการ
③ วิธีปันส่วน — การ์ดเดิมจาก FixedCostLockView (รายหัว / เท่ากัน / % ตามระดับ)
🔒 เมื่อล็อก: ทุกช่องอ่านอย่างเดียว + แสดงว่าล็อกเพราะหลักสูตรไหนยืนยัน/พิมพ์เมื่อไร · ปุ่ม “ปลดล็อก” เฉพาะกองแผน (ต้องกรอกเลขบันทึกข้อความ)

ร่างที่ยังไม่บันทึกเก็บเป็น draft มีปุ่มล้างร่าง และถ้าออกจากหน้าโดยยังไม่บันทึกจะถามยืนยันก่อน ตาม GUI conventions

4ข้อมูล & การล็อก

  1. โครงข้อมูล (ที่ทำจริง): แยกเก็บใน classStore.ts (ปี × คณะ) แต่ใช้ submitLock ของ lockStore ร่วมกัน เพราะถ้ารวมอยู่ใน record เดียวกัน การบันทึกการจำแนกจะไปตรึงวิธีปันส่วนให้เป็น “คณะตั้งเอง” ด้วย · แผนเดิม: เพิ่มฟิลด์ classification: Record<accountKey, {beh, f}> (เก็บเฉพาะแถวที่ต่างจากค่าตั้งต้น) ลงใน record เดิมของ lockStore (ปี × คณะ) ให้การจำแนกกับวิธีปันส่วนบันทึกและล็อกพร้อมกัน
  2. ลำดับค่าที่มีผล ต่อบัญชี: ค่าของคณะปีนี้ → ค่าของคณะปีก่อน → ค่าตั้งต้นมหาวิทยาลัย (account-rules ที่อนุมัติแล้ว → Excel)
  3. การล็อก: ใช้ submitLock เดิม และเพิ่มให้ “พิมพ์รายงานฉบับจริง” ล็อกด้วย ส่วนปลดล็อกให้ unlockSubmit บังคับกรอกเลขที่บันทึกข้อความ และเก็บประวัติ
  4. API ระบบบัญชี: ทำ adapter fetchExpenseAccounts(year) ไว้ก่อน ตอนนี้คืนรายการจาก Excel เมื่อได้ API จริงก็เปลี่ยนแค่ตัวนี้ ถ้ามีบัญชีใหม่ที่ไม่มีในค่าตั้งต้น จะแสดงเป็น “ยังไม่จำแนก” และติดธงให้ตรวจ
  5. ผลต่อการคำนวณ: ใช้กติกาเดิมของวิธีปันส่วน คือหน้าปรับปรุง/เปิดหลักสูตรใช้ค่าของคณะ ส่วนหน้า dashboard /faculty และรายงานยังตามชีต → ดู D5 · ต้องรอ AR-1/AR-2

5ต้องตัดสินใจ

D1 · ผู้บริหารคณะ (facultyExec) แก้ได้หรืออ่านอย่างเดียว มติเขียนว่า “เจ้าหน้าที่ระดับคณะ และ ผู้บริหารคณะ” ตั้งค่าได้ แต่ตอนนี้ระบบให้ผู้บริหารคณะอ่านอย่างเดียว (ตัดสินใจไว้ 22 ต.ค.)
เสนอ: ให้แก้ได้ตามมติ ทั้งการจำแนกและวิธีปันส่วน
D2 · คณะจำแนกที่ระดับไหน ก) หมวดรายจ่าย 12 หมวด (ง่าย แต่ไม่ตรง Excel เพราะหมวดเดียวมีทั้งคงที่และผันแปร) · ข) หมวดย่อย/คีย์ 4 ระดับ 113 รายการ (ตรง Excel) + ปุ่มตั้งทั้งกลุ่ม
เสนอ: ข) ตารางจัดกลุ่มตามหมวดรายจ่าย และมีปุ่มตั้งทั้งกลุ่มให้ทำเร็ว
D3 · ปีการศึกษา หรือ ปีงบประมาณ มติเขียน “ปีการศึกษา” แต่ข้อมูลต้นทุนจากกองคลังเป็นปีงบประมาณ ส่วนวิธีปันส่วนปัจจุบันใช้ปีชุดเดียวกับหน้าคำนวณ
เสนอ: ใช้ปีชุดเดียวกับวิธีปันส่วน (ปีที่เลือกบนหน้าคำนวณ) และแสดงป้ายว่า “ต้นทุนเป็นข้อมูลปีงบ …”
D4 · หน้ากติกาผังบัญชีระดับมหาวิทยาลัย (ที่ทำเมื่อเช้า) ยังต้องมีขั้นอนุมัติไหม มติไม่ได้พูดถึงการอนุมัติ ฝั่งคณะใช้การล็อกแทน แต่ค่าตั้งต้นมีผลกับทุกคณะที่ยังไม่ได้ตั้งค่า
เสนอ: คงขั้นอนุมัติไว้เฉพาะค่าตั้งต้นของมหาวิทยาลัย ส่วนคณะบันทึกแล้วมีผลทันที และล็อกเมื่อยืนยัน/พิมพ์ · ตัดช่อง “วิธีปันส่วน” ในหน้ากติกาผังบัญชีออก เพราะมติกำหนดวิธีปันส่วนเป็นระดับคณะ (ขั้น 3)
D5 · การจำแนกของคณะมีผลกับหน้าไหน ก) เฉพาะปรับปรุง/เปิดหลักสูตร (เหมือนวิธีปันส่วน) · ข) ทุกหน้ารวม dashboard คณะและรายงาน
เสนอ: ก) ให้ dashboard ยังตรงกับชีต เพื่อเทียบข้ามคณะได้ด้วยเกณฑ์เดียวกัน
D6 · “พิมพ์ฉบับจริง” คือปุ่มไหน ตอนนี้มีปุ่มพิมพ์/PDF ในหน้าปรับปรุงและหน้าหลักสูตรใหม่ ซึ่งพิมพ์ได้ทั้งฉบับร่างและฉบับจริง
เสนอ: ล็อกเฉพาะตอนพิมพ์หลัง Submit (ฉบับจริง) ฉบับร่างยังพิมพ์ได้โดยไม่ล็อก
✔ ตรวจแล้ว: ปุ่ม “ยืนยันและพิมพ์ฉบับจริง” Submit แล้วล็อกอยู่แล้ว ไม่ต้องแก้โค้ด

6ลำดับงาน

รหัสงานขนาด
CC-1เพิ่ม classification ใน lockStore + ลำดับค่าที่มีผล (คณะ → ปีก่อน → ค่าตั้งต้น) + เทสต์กลาง
CC-2หน้าตั้งค่า 3 ขั้น: ตารางจำแนกระดับคณะ + การ์ดวิธีปันส่วนเดิม + สถานะ/ล็อก + ร่างใหญ่
CC-3สิทธิ์ตาม D1 + เมนู (อาจารย์ไม่เห็น)เล็ก
CC-4ล็อกเมื่อพิมพ์ฉบับจริง (D6) + ปลดล็อกต้องกรอกเลขบันทึกข้อความเล็ก
CC-5ปรับหน้ากติกาผังบัญชีเป็นค่าตั้งต้นมหาวิทยาลัย (D4)เล็ก
CC-6adapter API ระบบบัญชี — กติกาตั้งต้นจาก Excel · กรองรายการตามงบ Oracle PPLN_BUDGET 2568 รายคณะ (scripts/import-oracle-expense-usage.mjs → oracleExpenseUsage.ts) · ปุ่ม “ใช้กับทุกแผนงาน” · ยังคงคีย์ 4 ระดับ (D2) เพราะ Excel จำแนกหมวดย่อยเดียวกันต่างแผนงานไม่เท่ากัน (เช่น 80001)เสร็จ 27 ต.ค. · รอ: ยอดเงินรายบรรทัด (AR-1) · ชื่อหน่วยงาน 2010927xxxxx 12 หน่วย
AR-1/2งบรายบรรทัดแยกคณะ + เครื่องคำนวณที่ตรงชีต (แผนเดิม) → ทำให้การจำแนกมีผลกับตัวเลขใหญ่

CC-1 ถึง CC-5 ทำได้ทันทีโดยไม่เปลี่ยนตัวเลขในระบบ ส่วนตัวเลขจะเปลี่ยนตามการจำแนกได้หลังทำ AR-1/AR-2 เสร็จ
