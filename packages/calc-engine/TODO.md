### ข้อ C — หลักฐาน (ตรวจโค้ด prototype ทั้ง 2 รุ่น)

`MSU-BEPS_03June26-1.html` ใช้ **TC** ทุกที่ — `pp = (tr-tc)/tc*100` ทั้งใน `renderBE()` และ `calcPg()`

แต่ **v8 ใช้ทั้งสองแบบปนกันในไฟล์เดียว**:

| ที่                                | โค้ด                                             | ตัวหาร |
| ---------------------------------- | ------------------------------------------------ | ------ |
| หน้าภาพรวม KPI + ข้อความสรุป       | `p / TRc(U) * 100` แล้วเขียนกำกับว่า "ของรายได้" | **TR** |
| Cross Analysis (`buildCrossData`)  | `(TR-TC)/TC*100`                                 | **TC** |
| เครื่องคำนวณรายหลักสูตร (`calcPg`) | `profit/TC*100`                                  | **TC** |

ผู้ใช้จึงเห็น "กำไร %" ของมหาวิทยาลัยเป็น 1.34% ในหน้าหนึ่ง และ 1.36% ในอีกหน้า
นี่คืออาการเดียวกับข้อบกพร่อง **#9** (นโยบายฝังในโค้ด แต่ละหน้าใช้กติกาต่างกัน)

**สิ่งที่ต้องทำ:** เพิ่ม key `profit_pct_basis` (`TC` | `TR`, default `TC` ตามโค้ดเดิมส่วนใหญ่)
เข้า `system_setting_def` แล้วให้ `calc-engine` รับเป็นพารามิเตอร์ — ห้ามฝังในโค้ด

### ข้อ D — หลักฐาน (ตรวจครบ 230 หลักสูตรใน `PG_DATA` ของรุ่น มิ.ย.)

**228 หลักสูตรตรงกับ `round(TFC / (R − AVC))` พอดี** — ยืนยันว่า prototype ใช้ `round` ไม่ใช่ `ceil`
(`ceil` ตรงเพียง 118 แถว · `floor` ตรง 110 แถว จึงเป็นไปไม่ได้ที่จะเป็นสองตัวนั้น)

เหลือ 2 แถวที่ไม่ตรง และ**เป็นแถว `type: "new"` ทั้งหมดที่มีในชุดข้อมูล**:

| หลักสูตร               | Q\* ที่แสดง | สูตรได้ | `type` | ข้อสังเกต   |
| ---------------------- | ----------- | ------- | ------ | ----------- |
| บัญชีบัณฑิต (บัญชีฯ)   | 242         | 238.85  | `new`  | **TVC = 0** |
| สัตวศาสตร์ (เทคโนโลยี) | 308         | 289.05  | `new`  | —           |

ความสัมพันธ์สมบูรณ์: `old` 228 แถว ตรงสูตรทั้งหมด · `new` 2 แถว ไม่ตรงทั้งคู่
บัญชีบัณฑิตมี `TVC = 0` ซึ่งเป็นไปไม่ได้ทางบัญชี — เป็นสัญญาณว่าแถวนี้กรอกมือ

**ข้อสรุป:** Q\* ของหลักสูตร `new` ไม่ได้มาจากสูตร แต่น่าจะเป็นเป้าหมายรับนิสิตจากเอกสารเสนอหลักสูตร
ยังต้อง**ยืนยันกับผู้พัฒนา** (มีแค่ 2 จุดข้อมูล) แต่หลักฐานหนักพอที่จะไม่ใช้ 2 แถวนี้เป็นค่าอ้างอิง

## สิ่งที่ตัดสินใจแล้ว — เขียนตามนี้ได้เลยเมื่อเริ่ม Sprint 1

1. **สูตรหลัก** (จาก SA.md หัวข้อ 7.1 · ยืนยันกับโค้ด prototype แล้วในหัวข้อ 16.3)

   ```
   TC  = TFC + TVC
   R   = TR / Q          → null เมื่อ Q <= 0
   AVC = TVC / Q         → null เมื่อ Q <= 0
   CM  = R - AVC
   Q*  = TFC / CM        เมื่อ CM > 0                    (สูตร 1)
   Q*  = TC / R          เมื่อ CM <= 0 และค่าตั้ง cm_le_zero_policy = full_cost_recovery (สูตร 7)
   Q*  = null            เมื่อ CM <= 0 และค่าตั้ง cm_le_zero_policy = not_computable
   การปัดเศษ Q* ตามค่าตั้ง qstar_rounding (ceil | round)
   BE Revenue = Q* × R                                   (สูตร 4)
   MoS = TR - BE Revenue
   π   = TR - TC                                         (สูตร 3)
   ```

2. **ฐานรายได้ 2 กรณี** (สูตร 5a/5b) — ต้นทุนเท่ากันทั้งสองกรณี เปลี่ยนเฉพาะฝั่งรายได้

   ```
   with_government    : TR = governmentBudget + incomeBudget
   without_government : TR = incomeBudget
   ```

3. **Q\* ระดับที่สูงกว่าหลักสูตร** (สูตร 6a/6b) — ค่าหลักมาจากค่าตั้ง `qstar_primary_method`
   (default `sum_of_programs`) ต้องคืนทั้งสองค่าเสมอเพื่อให้ UI เทียบได้
   และบันทึก `qstar_method` ลง `break_even_result`

   > **แก้ความเข้าใจผิดที่อยู่ในเอกสารเดิม** — SA.md สูตร 6 และหน้าสูตรของ prototype
   > เขียนว่าวิธีรายหลักสูตร "เข้มงวดกว่าเสมอ" / pooled "ได้ค่าต่ำกว่าความเป็นจริง"
   > **ไม่จริงในเชิงคณิตศาสตร์** มีตัวอย่างค้านใน `aggregate.test.ts` (sum = 681 · pooled = 690)
   > กลไก: หน่วยย่อยที่มี CM/หัว สูงกว่าค่าเฉลี่ยของหน่วยแม่มาก จะดึงผลรวมให้ต่ำลง
   >
   > ในข้อมูลจริงปี 2568 ทิศทางเป็นไปตามเอกสาร — 10 คณะที่ทุกหลักสูตรคำนวณได้
   > มี Σ > pooled ทุกคณะ (นิติศาสตร์เสมอกันเพราะมีหลักสูตรเดียว) — แต่เป็นลักษณะ
   > ของข้อมูลชุดนี้ ไม่ใช่ทฤษฎีบท UI จึงห้ามเขียนว่า "เสมอ"
   >
   > และ **v8 ใช้ pooled ทุกชั้นจริง** ทั้งที่หน้าสูตรอ้างว่าใช้วิธีรายหลักสูตรเป็นค่าหลัก —
   > คณะสัตวแพทยศาสตร์: Σ รายหลักสูตร = 486 แต่ค่าที่ v8 เก็บไว้คือ 477 (pooled)

4. **สถานะ `CM <= 0` ต้องไม่แสดงว่า "ผ่านจุดคุ้มทุน"** — prototype เก่าเขียน
   `isOk = !Qs || Q >= Qs` ซึ่งทำให้กรณีแย่ที่สุดขึ้น ✓ (SA.md หัวข้อ 16.3 ข้อ 3)
   ให้แยกสถานะ `full_cost_recovery` ออกมาชัดเจนตามที่ v8 ทำ

5. **Golden test** — ใช้ตัวเลขจาก **v8 + ไฟล์ `20260711_จุดคุ้มทุน update.xlsx`** เท่านั้น
