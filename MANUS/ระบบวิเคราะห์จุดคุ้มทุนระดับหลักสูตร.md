# ระบบวิเคราะห์จุดคุ้มทุนระดับหลักสูตร

## แนวทาง Cost Allocation, Mapping และโครงสร้างข้อมูล

## Slide 1 — Executive decision

**ข้อเสนอเพื่อขอความเห็นชอบ**

โครงการวิเคราะห์จุดคุ้มทุนระดับหลักสูตรสามารถดำเนินการได้ แต่ต้องอนุมัติกรอบข้อมูลและกติกาปันส่วนก่อนเริ่ม production

**สาระที่ขออนุมัติ:**

- ใช้ข้อมูล ERP และทะเบียนเป็นแหล่งข้อมูลหลัก โดยแยก direct cost ออกจาก allocated cost
- ใช้ mapping ผังบัญชีแบบคีย์ผสม 4 ระดับ ไม่ใช้รหัสบัญชีเดี่ยว
- อนุมัติคำนิยาม Q, ฐานต้นทุน, รายการ mixed cost และเจ้าของข้อมูล

## Slide 2 — ปัญหาที่ต้องแก้

**ข้อมูลสองระบบมีระดับความละเอียดไม่เท่ากัน**

ทะเบียนนิสิตละเอียดถึงรายหลักสูตรและรายนิสิต ขณะที่ ERP มักอยู่ระดับคณะ หน่วยเบิกจ่าย หรือสำนักงานเลขานุการ จึงไม่สามารถนำยอด ERP ไปผูกกับหลักสูตรโดยตรงทั้งหมดได้

> ตัวเลขจุดคุ้มทุนที่ดีต้องบอกได้ว่าส่วนใดเป็นต้นทุนตรง ส่วนใดเป็นต้นทุนที่จัดสรร และใช้กติกาใดในการจัดสรร

## Slide 3 — นิยามผลลัพธ์ทางธุรกิจ

| ตัวชี้วัด | ความหมาย                                               |
| --------- | ------------------------------------------------------ |
| Q         | จำนวนหน่วยกิจกรรม/นิสิตตาม snapshot และสถานะที่อนุมัติ |
| TR        | รายได้ของหลักสูตรในช่วงเวลาที่กำหนด                    |
| TFC       | ต้นทุนคงที่                                            |
| TVC       | ต้นทุนผันแปร                                           |
| BEP       | จำนวนผู้เรียนหรือรายได้ที่ทำให้รายได้เท่ากับต้นทุน     |

**จุดควบคุม:** ต้องกำหนดปีการศึกษา ปีงบประมาณ วันนับ Q และเกณฑ์รายได้ให้ตรงกัน

## Slide 4 — หลักการ Mapping

**Mapping ต้องเป็น master ที่มีช่วงเวลาและผู้อนุมัติ**

- หน่วยงาน: คณะ/ภาควิชา ↔ หน่วยเบิกจ่าย/ศูนย์ต้นทุน
- หลักสูตร: ใช้รหัสหลักสูตรเป็น key ไม่ใช้ชื่อไทยต่อข้อความ
- ผังบัญชี: แผนงาน + หมวดงบ + หมวดรายจ่าย + หมวดย่อย
- ประเภทนิสิต: ประเภท/สัญชาติ/รูปแบบการศึกษา ↔ ตารางค่าธรรมเนียม
- เวลา: ปีการศึกษา/ภาคเรียน ↔ ปีงบประมาณ

ทุก mapping ต้องเก็บ effective period, version, status, source reference และผู้อนุมัติ

## Slide 5 — จุดสำคัญของผังบัญชี ERP

**รหัสเดียวกันอาจมีประเภทต้นทุนต่างกันตามบริบท**

คีย์ที่แท้จริงคือคีย์ผสม 4 ระดับ ไม่ใช่รหัสย่อยเพียงตัวเดียว ตัวอย่างเช่นรหัส 80001 อาจเป็นต้นทุนคงที่, แบ่ง 50/50 หรือเป็นต้นทุนผันแปรตามแผนงาน

**ข้อเสนอ:** แยก `ERP_ACCOUNT_HIERARCHY` และ `BUDGET_CATEGORY_MAP` พร้อม `FIXED`, `VARIABLE`, `MIXED`, `UNCLASSIFIED` และอัตรา fixed/variable

## Slide 6 — วิธี Cost Allocation

**จัดสรรจากความสัมพันธ์จริงไปหาวิธีสำรอง**

1. Direct tracing เมื่อ ERP ผูกกับหลักสูตร/โครงการ/กิจกรรมได้
2. Actual usage เช่น ชั่วโมงสอน พื้นที่ FTE หรือการใช้บริการ
3. Student headcount เมื่อไม่มีข้อมูลการใช้จริง
4. Program share เมื่อไม่มี Q หรือ driver ที่ละเอียดพอ

สูตรหลัก: `Allocation_p = Cost pool × Driver_p / Σ Driver ของกลุ่มที่มีสิทธิ์รับต้นทุน`

## Slide 7 — การจัดการ Mixed Cost และการควบคุม

รายการ mixed cost ต้องแยก fixed และ variable ก่อนปันส่วน เช่น

`Fixed pool = Cost × fixed_ratio`

`Variable pool = Cost × variable_ratio`

**การควบคุมที่จำเป็น:** อัตรารวมต้องเท่ากับ 100%, denominator ห้ามเป็นศูนย์, driver ต้องอยู่ช่วงเวลาเดียวกัน และผลรวมปันส่วนต้อง reconcile กลับยอด ERP

## Slide 8 — Target ER และ Data Architecture

**แยก Source, Master, Allocation และ Analytics**

- Source: ERP cost, registration snapshot, fee transaction
- Master: time, organization, program, account hierarchy, student type
- Allocation: method, driver, run, result
- Analytics: program cost summary, BEP scenario, BEP result
- Governance: import batch, lineage, approval, data-quality issue

การแยกชั้นทำให้เปลี่ยนกติกาปันส่วนหรือประมวลผลซ้ำได้ โดยไม่เขียนทับข้อมูลต้นทาง

## Slide 9 — ข้อจำกัดฐานข้อมูลและความเสี่ยง

| ประเด็น              | ข้อเสนอควบคุม                                   |
| -------------------- | ----------------------------------------------- |
| Duplicate import     | unique source system + source record id + batch |
| Mapping ซ้อนช่วงเวลา | unique business key ตาม effective period        |
| Mixed ratio          | CHECK fixed ratio + variable ratio = 1          |
| จำนวนเงิน            | ใช้ DECIMAL และระบุ basis                       |
| ประวัติ master       | versioning/soft delete ไม่ hard delete          |
| ความน่าเชื่อถือ      | แสดง direct, allocated และ quality flag แยกกัน  |

**ความเสี่ยงสูงสุด:** หาก ERP ไม่มี dimension ถึงหลักสูตร ผลรายหลักสูตรจะเป็น allocated result ไม่ใช่ direct cost ทั้งหมด

## Slide 10 — Roadmap และมติที่ต้องการ

**Roadmap:** Discovery → Mapping Foundation → Pilot → Validation → Production

**มติที่ต้องการจากผู้บริหาร:**

1. อนุมัติให้ขอผังบัญชี 4 ระดับและผังหน่วยเบิกจ่ายฉบับเต็ม
2. อนุมัตินิยาม Q และกติกาปีการศึกษา/ปีงบประมาณ
3. อนุมัติว่าจะใช้เบิกจ่ายจริงหรือวงเงินอนุมัติเป็นฐานต้นทุน
4. มอบเจ้าของข้อมูลอนุมัติ mapping และรายการ mixed cost
5. เห็นชอบให้เริ่ม pilot ในหนึ่งคณะ/กลุ่มหลักสูตรก่อนขยายผล

**ข้อสรุป:** เป้าหมายไม่ใช่เพียงได้ตัวเลข BEP แต่ต้องได้ตัวเลขที่อธิบายที่มา ตรวจสอบย้อนกลับ และปรับสมมติฐานได้
